# Менеджер проектов (бывший «Полевой журнал»): что где хранится и как всё восстановить

Версия 1.0 (ещё под названием «Полевой журнал») — ветка `release-1.0`. С версии 1.1 один сайт для всех: настроек Firebase в коде нет, каждый подключает свою базу.

## 1. Из чего состоит приложение

| Часть | Где находится | Зависит от GitHub? |
|---|---|---|
| Код приложения | GitHub: `kukilvan/project-manager-app` (бывший `polevoy-zhurnal`; ветки `main`, `release-1.0`) | да |
| Сайт (то, что открывается на телефоне) | GitHub Pages: https://kukilvan.github.io/project-manager-app/ | да |
| Подключение к вашей базе (настройки Firebase + Client ID) | в телефоне; «☰ → Данные → Подключение к базе → Ссылка для подключения». **Сохраните эту ссылку** | нет |
| Данные всех проектов (точки, отчёты, история) | Firebase (Google), проект `polevoy-zhurnal`, база Firestore | **нет** |
| Вход через Google | Firebase Authentication | нет |
| Общий пул, список разрешённых почт, личные настройки (словарик и т. п.) | та же база Firestore | нет |
| Автокопия данных (каждые 2 дня) | GitHub: закрытый репозиторий `kukilvan/polevoy-backups` | да |
| Та же автокопия вне GitHub | Google Диск: «Менеджер проектов» (бывш. «Полевой журнал») → «Автокопия данных (обновляется каждые 2 дня).zip» (прошлые версии: «Управление версиями», ~30 дней) | нет |
| Ночное обновление таблиц для руководства | GitHub Actions (`server-tables.yml`) | да |
| Копии «Резервная копия на Диск», чертежи, инструкции, таблицы | Google Диск участников | нет |
| Ключи для серверных задач | GitHub → Settings → Secrets: `FIREBASE_SERVICE_ACCOUNT`, `BACKUP_REPO_TOKEN` | да |

Если GitHub пропадёт, **данные не пропадут**: они в Firebase. Пропадут сайт, код, автокопии и ночные задачи — их и нужно держать копией вне GitHub.

## 2. Что сохранить у себя (вне GitHub)

1. Архив кода `polevoy-zhurnal-v1.0.zip` (в нём полная история git: `polevoy-zhurnal.bundle`, исходники и готовая сборка `dist/`).
2. Свежая автокопия данных сама приходит на Google Диск (файл выше). Дополнительно, на случай потери Диска: на GitHub открыть `kukilvan/polevoy-backups` → зелёная кнопка **Code → Download ZIP**. Положить рядом с архивом. Повторять, например, раз в месяц.
3. Ключ сервисного аккаунта Firebase (JSON). Хранить только в личном месте (Google Диск «только я», флешка). В репозиторий и чужим людям — никогда. Если ключа нет, его в любой момент можно создать заново (см. п. 5.3).
4. Время от времени — «☰ → Данные → Резервная копия на Диск» по каждому проекту (это копия, которую можно залить кнопкой «Импорт данных»).

## 3. Достать код из архива

```
unzip polevoy-zhurnal-v1.0.zip
git clone polevoy-zhurnal.bundle polevoy-zhurnal     # полная история и все ветки
cd polevoy-zhurnal
git branch -a                                         # main, release-1.0, stable-…
npm ci && npm test && npm run build                   # нужен Node.js 22
```

## 4. Поднять сайт на другой площадке (если GitHub недоступен)

Подойдёт любой хостинг статических сайтов: Firebase Hosting (тот же Google, удобнее всего), Cloudflare Pages, Netlify, GitLab Pages.

1. В `vite.config.js` поменять `BASE`:
   - сайт в корне домена (Firebase Hosting, Cloudflare, Netlify) → `const BASE = '/';`
   - сайт в подпапке → `'/имя-подпапки/'`.
   (или задать при сборке: `VITE_BASE=/ npm run build`).
2. `npm run build` → залить содержимое папки `dist/` на хостинг.
   - Firebase Hosting: `npm i -g firebase-tools`, `firebase login`, `firebase init hosting` (папка `dist`, «single-page app» — да), `firebase deploy --only hosting`. Адрес будет `https://<id-проекта>.web.app`.
3. Разрешить вход с нового адреса:
   - Firebase Console → Authentication → Settings → **Authorized domains** → добавить новый домен.
   - Google Cloud Console (проект `polevoy-zhurnal`) → APIs & Services → Credentials → OAuth-клиент «Web client (auto created by Google Service)» → **Authorized JavaScript origins** и **Authorized redirect URIs** → добавить новый адрес (нужно для Диска и Таблиц).
4. На телефонах удалить старую иконку, открыть новый адрес и подключиться по сохранённой «Ссылке для подключения» (в ней старый адрес — замените в ней начало до `?connect=` на новый адрес). Данные на месте — они в Firebase.

## 5. Серверные задачи (автокопия и ночные таблицы) без GitHub

Сейчас их запускает GitHub Actions. На другой площадке (GitLab CI, свой компьютер или Raspberry Pi по расписанию cron) команды те же:

```
npm i --no-save firebase-admin@13 google-auth-library@9 mupdf@1.28.1
FIREBASE_SERVICE_ACCOUNT="$(cat ключ.json)" node scripts/server-backup.mjs папка-для-копий   # копия, раз в 2 дня
FIREBASE_SERVICE_ACCOUNT="$(cat ключ.json)" node scripts/server-drive-backup.mjs папка-для-копий   # её zip — на Google Диск
FIREBASE_SERVICE_ACCOUNT="$(cat ключ.json)" node scripts/server-tables.mjs                   # таблицы, раз в сутки
```

5.3. Новый ключ: Firebase Console → ⚙ Project settings → Service accounts → **Generate new private key**. Старый ключ после этого лучше удалить там же (Google Cloud Console → IAM → Service accounts → Keys).

Сервисный аккаунт должен иметь доступ к папкам руководства на Диске — приложение даёт его само (кнопка «Обновить таблицу для руководства»).

## 6. Если потерян сам проект Firebase (худший случай)

1. Создать новый проект в https://console.firebase.google.com, включить Firestore (режим production) и Authentication → Google.
2. Открыть сайт приложения → «⚙ Подключение» (или «☰ → Данные → Подключение к базе → Отключиться») и пройти мастер настройки с новым проектом: он сам ведёт по всем шагам и даёт правила базы.
3. Правила базы — из мастера (это `firestore.open.rules` в репозитории). Первый вошедший станет администратором: войдите первым сами.
4. Восстановить данные из последней автокопии (папка вида `2026-10-23_0830` из `polevoy-backups` или из zip-файла автокопии на Диске):
   ```
   npm i --no-save firebase-admin@13
   FIREBASE_SERVICE_ACCOUNT="$(cat новый-ключ.json)" node scripts/server-restore.mjs путь/к/папке            # проверка
   FIREBASE_SERVICE_ACCOUNT="$(cat новый-ключ.json)" node scripts/server-restore.mjs путь/к/папке --write    # запись
   ```
   Восстанавливаются все проекты (с историей и участниками), общий пул, список разрешённых почт и личные настройки.
   Отдельный проект можно вернуть и без этого: войти в приложение, создать проект и «☰ → Данные → Импорт данных» с файлом `… (импорт).json` или копией с Диска.
5. Собрать и выложить сайт (раздел 4).

## 7. Что не входит в архив

- Документы в проекте Claude «Менеджер проектов» (планы, промпты, файлы точек по чертежам заказчика) — они хранятся в Claude, не на GitHub.
- Чертежи заказчика и рабочие данные — только в Firebase и на Google Диске (в открытый репозиторий их не кладём).
- Старый Apps Script для таблиц руководителей (времён AppSheet) — больше не используется, лежит в проекте Claude.
